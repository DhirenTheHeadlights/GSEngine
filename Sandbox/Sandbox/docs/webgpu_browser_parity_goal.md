# Goal: the browser WebGPU frame matches native, and textured scenes load

## Aim

Close the open items from the browser-render cycle. The browser frame must be shown to equal the native WebGPU frame, not just be non-black. It must work in headed Chrome as well as headless. Textured `.gmodel` scenes must load in wasm. The leftover gaps from the cycle must each be closed or documented as a decision.

Native C4 (the blue deficit on lit geometry) is **not** in this goal. It already belongs to `docs/webgpu_backend_goal.md` (criterion C4, ledger 2026-11-02), and two goals editing the same shaders would collide. Steer it there.

## Pass criteria

All are checked from artifacts under `Tools/parity_reports/<stamp>/`, written by `Engine/cmake/wasm/host_gate.mjs` (extended) or a sibling script:

- **B1 Image parity.** `lighting_parity` runs at a resolution pinned by the scenario. The browser readback is compared against a native `Graphics.backend=webgpu` capture at the same size. Pass: mean absolute difference ≤ 2.0 per channel, and ≤ 1% of pixels with a delta over 8. Must hold on 3 consecutive runs.
- **B2 Headed Chrome.** The `render` case passes in headed Chrome (zero WebGPU errors, hash `0x350203be5257f128`, the native hash since the B1 determinism fix, canvas ≥ 50% lit) on 3 consecutive runs. The report records the browser version and mode.
- **B3 Textured scene.** A scenario that renders a textured model runs to exit in the browser. The tree has no textured `.gmdl`, so the model is a primitive box carrying a baked texture through `material_spec.diffuse_texture_name` (owner decision, task 91). Pack decompression with a sha256 check is not part of it; see Decisions. Its world-state hash must be stable across 3 runs. Its frame must pass B1's thresholds against native.
- **B4 Boot cost.** The report records the browser boot time spent computing the shader-tree digest. Pass: ≤ 250 ms, or a fix that brings it under that.
- **B5 Gaps.** Each remaining item is either implemented or listed in the record as an accepted decision: `mappedAtCreation`, timestamp/occlusion queries, non-WGSL shader modules over the wire, and the fifo-only present mode. Fifo-only is expected to be accepted, since the browser exposes nothing else.
- **No regression.** In every report: native WebGPU still hashes `0x350203be5257f128`, the existing `host_gate.mjs` cases still pass 3/3, and native Vulkan/DX12 hashes are unchanged.

## Decisions (B5)

- **`mappedAtCreation`: not implemented, accepted.** Every buffer the WebGPU backend creates passes `mappedAtCreation = false` (`WebGpu/Device.cppm` at the three `wgpuDeviceCreateBuffer` descriptors). Uploads go through queue writes and staging copies, which already cross the wire. `Web/Wire.cpp` asserts on `mappedAtCreation`, so a future caller fails loudly instead of silently. Revisit only when a caller needs it: it would be a second map path over the wire, and nothing uses it.
- **Timestamp and occlusion queries: deferred, accepted.** The WebGPU backend has no query pools on either arm. `gpu::webgpu_device_backend::create_timestamp_query_pool` and `create_pipeline_stats_query_pool` return a null handle, and `query_pool_results` returns `query_status::error`. `webgpu::commands` query calls assert `!pool`, and the wire asserts on `timestampWrites` and `occlusionQuerySet`. Effect on the profiler: `render_graph` gets `ts_status != success`, marks the slot's results invalid, and records no GPU spans, intra-pass marks or pipeline stats. Only CPU timings appear. `timestamp_period()` is 1 and `calibrated_timestamp` is `nullopt`. The gate adapter (headless Chrome, intel xe-2lpg) does offer `timestamp-query` (run `Tools/parity_reports/2026-11-04T17-11-46-301Z/`), and the page already forwards it (`page/gpu.mjs` FEATURES), so the missing piece is engine-side only: enabling queries later needs query-set creation, resolve and readback on both arms plus wire commands. That is a feature cycle, and Chrome quantises timestamps to 100 µs by default.
- **Non-WGSL shader modules: accepted as is.** The bake emits only WGSL (`store_wgsl` in `GpuRecord/Native/ShaderCompile.cpp`). The device builds only `WGPUShaderSourceWGSL` modules, and `Web/Wire.cpp` asserts that the chained source is `WGPUShaderSourceWGSL`, so anything else fails loudly.
- **Fifo-only present mode: accepted.** The browser canvas has no present-mode choice. The wire reports surface caps with only `WGPUPresentMode_Fifo`, and `configure_surface` falls back to fifo and logs `fifo_fallback=true` when another mode is requested.
- **Wasm pack decompression and sha256 (B3, `wasm_quality_goal.md` row 44): not applicable, accepted.** Baked assets (`.gmdl`, `.gsmdl`, `.gtx`) are raw `binary_writer` files with no codec, and the browser fetches them as they are. The LZMS pack and its sha256 (`Sdk/Pack.cppm`, Win32 Compression API) are only the installer payload, and no browser code path reads them, so `Sdk/Web/Pack.cpp` stays stubbed. Compressed delivery for a hosted build belongs to HTTP gzip/brotli, and integrity belongs to HTTPS. Revisit only if an in-browser installer or a packed asset tree appears.
