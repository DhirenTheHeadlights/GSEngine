# Goal: Canonical formatting for all C++ in the codebase

## Aim
Make the code panel's Format, format-on-save and `gse_format` put every C++ source file the project owns (*.cpp, *.cppm, *.h/*.hpp we wrote; vendored code excluded) into a single canonical layout. Formatting a formatted file then changes nothing anywhere in the tree. The work still goes one construct at a time: agree on a shape, teach `Engine/Code/Source/Format/Formatter.cppm` to emit it, and verify on real files. It ends with an owner-approved tree-wide reformat. Literal text and identifiers are never changed. Only whitespace, line breaks and owner-approved token rules (import ordering, trailing commas) move.

## Pass criteria
1. **Catalogue.** This record keeps a list of construct kinds, each marked `agreed-format`, `implemented`, `verified` or `out-of-scope (owner)`. Already `verified`: annotation blocks, import blocks, brace/indent of namespaces/structs/functions, enum bodies, initializer lists, signatures/parameter lists, call-argument wrapping, lambdas, requires/template headers, switch/case, blank-line policy, if/else chains. Added and unmarked:
   - expression wrapping: long binary/logical chains, ternaries, conditions and the mid-expression call break;
   - chained calls and range pipelines (`|`, `.`, `->` chains);
   - constructor member-initializer lists;
   - control-statement headers: `for`/`while`/`do`/`if` with init-statements, including the for-header call split;
   - multiple statements on one line, including one-line bodies holding several statements;
   - intra-line spacing: operators, commas, keyword-paren, cast/unary, `template <`, braces' inner padding;
   - pointer/reference placement (`T& x`);
   - declarations: one member/variable per line, `using`/alias and concept definitions;
   - `extern "C" {`/`export {` blocks and `alignas`/attribute-headed class heads;
   - `)(`/`](` call heads and `));` inside casts;
   - long string-literal concatenation and long `<<`/stream chains;
   - leading `template <T> requires C<T>` declarations;
   - comment and preprocessor-adjacent code (indent of `#if` regions; comments are never edited);
   - file hygiene: trailing whitespace, final newline, line endings, tabs/spaces per setting;
   - display-width columns instead of byte-counted width.

   Steering adds any other kind the tree-wide survey (criterion 4) turns up.
2. **Each construct is verified on real files.** For each `implemented` kind, at least 3 real files from different modules are formatted. The run confirms (a) a before/after excerpt in the ledger, (b) a zero-edit second pass and (c) green Editor and Sandbox `gse_build`s with the formatted files. Only then does the kind move to `verified`.
3. **No regression.** Every previously `verified` kind's sample files still give zero edits on a second pass after each later construct lands.
4. **Tree-wide coverage.** A dry-run format of every owned C++ file makes zero edits on a second pass, and none of them are skipped or bailed out of. A steering survey of the formatted output finds no residual non-canonical instance of any catalogued kind, apart from instances the owner has marked out of scope.
5. **Tree-wide reformat.** With the owner's approval (asked when criteria 1–4 hold), the whole tree is formatted for real. Editor and Sandbox builds succeed, and a further full-tree format makes zero edits.
6. **Style guide.** `docs/STYLEGUIDE.md` describes every agreed shape, in wording the owner approved.
7. **Done.** Every catalogue entry is `verified` or `out-of-scope (owner)`, criteria 2–6 hold, and the owner confirms the result.

## Charter
- **No asking needed:**
  - editing `Engine/Code/Source/Format/Formatter.cppm`, new formatter-only helpers under `Engine/Code/Source/Format/`, and the format plumbing in `Editor/Editor/Source/App/CodePanel.cppm`;
  - the `gse_format` tool and its plumbing: `Tools/gse-mcp/server.mjs`, the `formats` queue in `Editor/Editor/Source/BuildRunner/Inbox.*`, `Editor/Editor/Source/FormatQuery/`, and its entries in `Editor/Editor/Source/Agent/Session.cppm`/`Model.cppm`;
  - queuing builds through `gse_build`;
  - formatting sample files for verification and then reverting them;
  - dry-run (non-writing) formats of any owned file for the tree-wide survey;
  - updating this record's ledger and catalogue states;
  - adding catalogue kinds found by survey.
- **Must ask the owner (`gse_ask`) every time:**
  - the canonical shape of each construct, offering 2+ layouts drawn from the tree's dominant usage with a recommendation;
  - any rule that reorders or inserts tokens (inserting braces around unbraced bodies is outside the goal unless the owner asks);
  - marking a kind `out-of-scope`;
  - any formatting written to files outside the verification samples, including the criterion-5 reformat, which should be offered in batches by module if the owner prefers;
  - STYLEGUIDE.md wording.
- **Off limits:** `settings.ini`, other chats' files (dry-run on byte copies only), vendored code (`Engine/External/**`, vcpkg trees, moodycamel), TokenPlugin unless the owner opts it in, comments in code (none, per CLAUDE.md), and Slang shaders (not C++).
- **Process per construct:** survey real occurrences, ask for the shape, then implement the smallest pass that composes with the existing pipeline and takes the format options. Verify per criterion 2, re-check criterion 3, then record the result in the ledger.
