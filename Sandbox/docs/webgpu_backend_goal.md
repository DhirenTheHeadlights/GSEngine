# Goal: a clean WebGPU backend for GSE

## Aim

Add WebGPU as a third GPU backend next to Vulkan and DX12, behind the same `gse.gpu` seam DX12 proved (`backend_kind` in `GpuBackend/Enums.cppm`, device dispatch in `Gpu/Device/Device.cpp`, the shader-codegen branch in `GpuRecord/PipelineBuilder.cpp`). The point is that the browser port can render as well as tick. `docs/wasm_browser_goal.md` leaves WebGPU for the next goal; this is that goal.

"Clean" means:
- **One backend, not a renderer fork.** Only `Gpu/` and the new `WebGpu/` units know WebGPU exists. The backend is written against the standard `webgpu.h` C API, so the same code runs on native wgpu-native and in the browser.
- **No WebGPU branches in the renderers.** WebGPU has no ray tracing, so lighting is split behind a technique seam: a Slang interface (`IShadowVisibility`, `IAmbientOcclusion`) that `forward.slang` calls without knowing the implementation. The concrete module (`shadow_rt.slang` / `shadow_raster.slang`, RT-AO / GTAO) is chosen at pipeline build through Slang link-time specialization.
- **CPU side mirrors it.** `rt_shadow` and a new `raster_shadow` (sun cascades + local-light atlas/cubes) each publish one `shadow_source` contract: bindings plus the pass to wait on. `forward` reads `shadow_source` and no longer imports `rt_shadow` (today it does, at `ForwardRenderer.cpp:29/143/302/312/371`). AO works the same way. Exactly one implementation is registered, picked once at system registration from the device capability report, never by checking `backend_kind` in a renderer.
- **The raster path is first-class on every backend.** It's a quality setting on Vulkan and DX12 too (useful on Intel Arc and low-end GPUs), so it's exercised natively and doesn't rot. WebGPU simply always gets it because it reports no ray queries.

## Milestones (in order)

1. **Technique seam + raster lighting on Vulkan.**
   - Add the Slang interfaces and refactor `forward` onto them.
   - Add `raster_shadow` and GTAO systems.
   - Add a shadow-technique setting with registration-time selection.
   - Audit every shader using `RayQuery`/TLAS (GiProbe in particular) and give each one a non-RT implementation behind the same seam (for GiProbe: raster probe capture or static probes).
   - No WebGPU code in this milestone.
2. **WebGPU device plumbing, native.**
   - `backend_kind::webgpu`.
   - The WGSL arm of the Slang codegen.
   - Vendored, pinned wgpu-native.
   - Bindless mapped to bind groups / binding arrays.
   - Timestamps optional.
   - Capability report says no ray queries.
3. **Browser leg.** Once `wasm_browser_goal` is met, the same scenario renders in a browser page.

## Pass criteria

All checked from artifacts:

1. **Milestone 1 holds.**
   - On Vulkan, the parity rendering scenario on the ray-traced path produces the same world-state hash, and a frame within image tolerance, as the pre-goal baseline (the refactor changed nothing).
   - The same scenario with `--engine-setting <shadow technique>=raster` runs to exit 0 with no validation errors and no `RayQuery` pipeline bound (checked from the log or the pipeline list).
   - DX12 does the same on both paths.
2. **WebGPU native.** With `--engine-setting Graphics.backend=webgpu` (exact name to be confirmed) on Windows/wgpu-native, the same scenario exits 0 with no WebGPU validation or device-lost errors.
3. **Hash parity.** The world-state hash on WebGPU equals the Vulkan run's.
4. **Image parity.** The final presented frame on WebGPU matches the **Vulkan raster-path** frame within a tolerance written into the harness.
5. Criteria 1–4 hold on 3 consecutive runs, and the harness writes a report artifact under `Tools/`.
6. **Browser leg** (`require` only once `wasm_browser_goal` is met, `report` before that): the scenario renders in a browser page with no WebGPU console errors.

- New `Engine/Engine/Source/WebGpu/**`, and `:*_impl` units under `Gpu/` and `GpuBackend/` adding the webgpu arm.

- `gse_run` with `--engine-setting` overrides, and long builds.
- This record's ledger.

**Escalate to the owner:**
- Any change to ray-traced output, hashes or defaults on Vulkan/DX12, or to the default backend or default shadow technique.
- Restructuring the render graph or the `gse.gpu` seam beyond adding the webgpu arm and module selection.
- Removing an effect outright instead of giving it a second implementation.
- A `backend_kind` check inside a renderer. If one seems needed, that's a design question.
- Choosing Dawn over wgpu-native, or bumping the pinned version.
- Experimental wgpu native ray queries.
- Anything under the wasm toolchain or `Os/` (owned by the wasm goals).
- Commits and pushes, and `settings.ini`.
