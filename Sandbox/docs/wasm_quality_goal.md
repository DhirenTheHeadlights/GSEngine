# Goal: bring the WASM work up to the owner's standard

## Aim

The WASM port works: a headless scenario ticks in a browser with native world-state parity. The owner now wants that work brought to a standard they are satisfied with before it is built on further. That means the layout, idiom, style and review-guide compliance of everything the port added or changed, not new capability. The first known defect is platform implementation `.cpp` files living in `Engine/Engine/Import/`. More will come from the owner's own file-by-file review.

## Pass criteria

A steering run decides from artifacts:

1. **Every review group below is marked `accepted` in the ledger**, and each acceptance quotes an owner answer collected with `gse_ask`. Satisfaction is the owner's verdict. A steering run never infers it.
   - G1 plan docs (`docs/wasm_pipeline_plan.md`, `Sandbox/docs/wasm_browser_goal.md`, `docs/TOOLCHAIN_SETUP.md` wasm parts, `Tools/gcc-toolchain/wasm/README.md`)
   - G2 GCC patches `Tools/gcc-toolchain/wasm/0002`–`0020` local patches
   - G3 toolchain/build scripts (`Tools/build_gcc_wasm.py`, `msys2.py`, `install_msys2.py`, `wasm_dialect_probe.py`, `libm_probe/`, `module_graph.py`)
   - G4 engine CMake arm selection (`Engine/cmake/GSEEngine.cmake`, `platform_impl_arms.txt`, `excluded_impl_units.txt`, `native_gpu_backend_units.txt`)
   - G5 core module impls (assert/log/config/shell/stacktrace, after task 1)
   - G6 runtime/time/concurrency `Web/` arms
   - G7 OS + process `Web/` arms
   - G8 fs/assets/sdk `Web/` arms
   - G9 GPU/graphics `Web/` stubs
   - G10 diag/audio/network/http/server `Web/` arms
   - G11 browser host + gates (`Tools/wasm_page/*.mjs`, `run_wasm_page.py`, `wasm_parity_gate.py`, `wasm_divergence.py`)
   - G12 repo hygiene (`.gitignore`/`.gitattributes`; no `.gcc-wasm*.log` or `.gcc-wasm-run/` artifacts tracked)
2. **No regressions, held across the final 2 consecutive steering checks:** native `gse_build` is green, and the wasm parity gate (`Tools/wasm_parity_gate.py` on `scene_reset_cpu`) still passes with the same hash identity and positional criteria `Sandbox/docs/wasm_browser_goal.md` set.
3. **Mechanical standards hold in every C++ file in G5–G10:** zero comments (`.claude/CLAUDE.md`), `docs/STYLEGUIDE.md` conventions, and no `.cpp` under `Engine/Engine/Import/`.

## Charter

**Authorized, no asking:**
- Task 1, already scoped: move the 15 `.cpp` impl units of gse.assert/log/config/shell/stacktrace from `Engine/Engine/Import/{,Win32/,Web/}` to `Engine/Engine/Source/<Module>/{,Win32/,Web/}`. The `.cppm` primary interfaces stay in `Import/`. Uncommitted edits move byte for byte. Fix the live path mentions in `Tools/module_graph.py:151`, `Tools/build_gcc_wasm.py:1604` and `docs/game_distribution_plan.md:26`. History in the goal and plan docs stays as written.
- Structural moves, renames, deleting dead or duplicated code, removing comments from C++, and style and review-guide fixes inside files in groups G1–G12. Each must be behaviour-preserving: native hash unmoved, wasm parity green.
- Fixing anything the owner raises in a review answer, within those files.
- `gse_build`, `gse_run` with scenarios and `--engine-setting` overrides, the wasm sweep, the parity gate.
- Presenting one review group at a time to the owner via `gse_ask` (accept / list of objections), and recording the answer in the ledger.

**Owner's call, escalate:**
- Anything that changes native behaviour or a native world-state hash, or deletes or disables a native code path.
- Re-cutting an applied GCC patch (its stamp keys on patch bytes), or changing what a patch does rather than how it reads.
- Module renames or partition-structure changes (e.g. folding gse.log into gse.diag), new modules, or changes to the arm-selection mechanism itself.
- Files outside G1–G12, or files another chat is editing.
- New capability (WebGPU, renderer, exceptions work): that is the next goal, not this one.
- Commits, pushes, PRs. The owner commits.
- Reverting previously working code to chase a new bug.

**Off limits:** editing `settings.ini`; invoking cmake/ninja/compilers directly.
