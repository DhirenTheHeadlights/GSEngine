# Units that exist only for a native GPU backend, as repo-relative paths. A configuration
# without one -- wasm32 is the only such configuration today -- omits them. Interface units
# and implementation units both: the list is read against the .cppm walk and the .cpp walk
# alike, because "needs a platform GPU backend" is a property of the unit and not of its
# suffix.
#
# ONE DECLARATION, READ BY TWO ENUMERATORS, which is why this is a data file and not a
# directory test. CMake builds the link (gse_drop_native_gpu_backend_units in
# GSEEngine.cmake, applied to the interface list and the impl list both);
# Tools/module_graph.py builds the wasm sweep's unit list by walking the source tree, and
# build_gcc_wasm.py offers it everything that walk returns. A rule written in only one of
# them holds for only one of them: a CMake-only exclusion moves no sweep number, and a
# sweep-only exclusion measures a link nobody can produce. Two copies of the test is the
# outcome worse than either -- see module_graph.py's `wraps_host`, which exists because
# that test had two copies.
#
# Three partitions of gse.gpu that reach a platform GPU backend, plus the one impl unit
# that imports such a partition directly. gse.gpu's import discipline is what lets the
# partitions go: their only importers are Gpu/Device/Native/DeviceCreate.cpp and
# Gpu/Device/Native/DeviceVideo.cpp -- both the Native arm of a platform choice, so a wasm
# link is never offered either -- and Gpu/Device/VideoEncoder.cpp, which is why that unit
# is named here too. No surviving interface unit loses an edge.
#
# The backends' own modules are deliberately absent -- Vulkan/Aftermath.cppm is imported by
# Vulkan/Device.cppm and re-exported by Import/Vulkan.cppm, so dropping it would break
# native, and with these gone nothing reachable from the gse umbrella imports gse.vulkan or
# gse.dx12 anyway.
